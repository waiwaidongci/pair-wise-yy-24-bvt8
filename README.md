# 电台播出与版权窗口排程

一个不依赖第三方包、使用 SQLite 和标准库 HTTP 服务的电台排程项目。系统把“计划排期”和“实际播出”分开保存，支持地区授权、日期窗口、禁播时段、节目冷却、赞助商间隔、直播临时替换、实播对账与版权越界检查。

## 播出日与时间轴

- **播出日 06:00 切日**：一个播出日覆盖当天 06:00 到次日 06:00。钟点早于 06:00 的凌晨档（如 02:00）自动归入前一播出日，落盘时存成绝对时刻（如播出日 `2026-09-28` 的 `02:00` = `2026-09-29T02:00`）。
- 节目可以从前一晚 23:xx 开播、一直连到次日凌晨；时段内部统一以 `start_at/end_at` 绝对时刻存放。
- **重叠、地区/日期授权、禁播、冷却、赞助商间隔全部在时间轴上判断**，查询时向相邻播出日两侧放宽，跨零点节目不再和次日凌晨档“撞而不报”。
- 禁播窗口允许跨日（`start_time >= end_time`，如 `23:00–02:00`），写入与旧数据升级时都拆成“当日深夜 + 次日凌晨”两段（段自身不跨日历日），校验按星期逐日落段。
- 授权日期窗口按节目覆盖到的每个日历日检查（跨零点会盖两天）。
- 冲突信息会说明撞到的具体排期：档口号、节目名、绝对起止时间。移动/替换是整盘重校验，任一冲突即回滚，**原安排保留**。

## 并发与历史版本

- 每个播出日维护一个版本号（`day_versions`，页面上显示）。提交排期/移动/替换时可带 `expected_version`；版本过期返回 **409**，响应体 `day` 字段携带该播出日最新时段，后提交的编辑先看到对方已改内容，带新版本重试即可。跨播出日移动时还可用 `expected_target_version` 同时核对目标日。
- 服务端用 `BEGIN IMMEDIATE` 串行化写事务，并在进程内加锁，保证两名编辑的并发提交按序落盘。
- 每次移动/替换都写入 `slot_revisions`；**登记实播时钉住当时的计划版本与计划时刻**，对账始终按实播当时的版本比，事后再移动或替换不会改写历史。

## 旧数据升级

打开旧版数据库（`slots` 只有 `air_date + start_time`）时自动迁移：

- 时段按**开播时刻**重新归入播出日（凌晨档归前一天），并生成绝对 `start_at/end_at` 与首版修订；
- 跨日禁播窗口拆成两段；
- 旧实播记录按旧排期日历日期补全绝对时刻，钉住第 1 版计划。

## 运行

需要 Python 3.11+。

```bash
python app.py
```

默认端口为 `8111`，页面地址是 <http://127.0.0.1:8111>。第一次启动会创建 `radio.db` 并写入演示排期（含一条 23:30 开播连到次日 01:00 的跨零点节目）。也可以设置端口和数据库位置：

```bash
PORT=9000 RADIO_DB=/tmp/radio.db python app.py
```

## 测试

```bash
python -m unittest discover -s tests -v
```

测试覆盖：凌晨档归日、跨零点重叠、跨零点移动/替换的双侧校验与原安排保留、跨日禁播拆分、跨零点冷却与赞助间隔、授权日期跨日、乐观并发 409 与写锁串行化、实播钉版本对账，以及旧库自动升级。

## 主要 API

- `GET /api/state`：节目、按绝对时间排列的排期、禁播段、各播出日版本号、最近对账异常
- `POST /api/programs`：创建节目并授权地区
- `POST /api/programs/{id}/regions`：追加地区授权
- `POST /api/schedule`：创建排期（`air_date` 为播出日；可选 `expected_version`）
- `POST /api/slots/{id}/move`：移动档口到新播出日/钟点（`air_date`、`start_time`；可选 `expected_version`、`expected_target_version`）
- `POST /api/slots/{id}/replace`：替换计划节目并在时间轴上重新校验
- `POST /api/playout`：登记实播记录（`actual_start` 可给 `HH:MM`，跨零点自动选离计划最近的日历日；也可给绝对时刻）
- `POST /api/reconcile`：按播出日生成漏播、错播、时长偏差和超授权异常（按实播当时版本）

准备排期时填写播出日 `air_date`、`start_time`、`program_id`、`region`。页面会直接显示校验错误（含撞到的排期），不会保存失败的排期；并发冲突时会标出对方最新的时段。
