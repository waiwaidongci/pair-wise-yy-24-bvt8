# 电台播出与版权窗口排程

一个不依赖第三方包、使用 SQLite 和标准库 HTTP 服务的电台排程项目。系统把“计划排期”和“实际播出”分开保存，支持地区授权、日期窗口、禁播时段、节目冷却、赞助商间隔、直播临时替换、实播对账与版权越界检查。

## 播出日（早上六点切分）

播出日不再按自然日划分，而是以**早上 06:00** 为界：播出日 `D` = `[D 06:00, D+1 06:00)`。凌晨 `00:00–05:59` 的档口归入**前一天**播出日，例如 `2026-09-28 02:00` 属于播出日 `2026-09-27`。

节目可以从前一晚连到次日（如 `23:00–01:00`）。所有校验都在连续时间轴上进行：

- **重叠**：按整条时间区间判断，跨零点节目会和次日凌晨档口相撞；
- **授权**：按播出日判断是否在授权窗口内；
- **禁播**：跨日禁播窗口（如 `23:00–02:00`）拆成两段同日内窗口（`23:00–24:00` 与次日 `00:00–02:00`），节目横跨哪一段就校验哪一段；
- **冷却 / 赞助间隔**：按时间轴上的绝对间隔判断，跨零点也不会漏。

## 旧数据升级

首次打开旧数据库时会自动迁移：

- 排期按开播时刻归入播出日（`06:00` 前归前一天）；
- 跨日禁播窗口拆成两段；
- 实播记录补登播出当时的计划快照。

## 编辑协作

- **移动 / 替换**：`POST /api/slots/{id}/move` 与 `POST /api/slots/{id}/replace` 一次校验跨零点节目的两侧，冲突会说明撞到哪条计划（如 `与排期 #12 时间重叠`），失败时原安排保持不变。
- **并发提交**：两个编辑修改同一播出日时，后提交者必须先看到对方已改的时段。提交时带上 `base_version`（来自 `GET /api/state` 或 `GET /api/plan?date=`）；若该播出日已被他人改过，接口返回 `409` 并在 `state` 里给出对方已改的时段，刷新后再提交即可。
- **实播对账**：登记实播时会快照播出当时的计划版本；之后再移动或替换节目，已登记的实播仍按播出当时的版本进入对账，不会被事后改动改写。

## 运行

需要 Python 3.11+。

```bash
python app.py
```

默认端口为 `8111`，页面地址是 <http://127.0.0.1:8111>。第一次启动会创建 `radio.db` 并写入三条演示排期。也可以设置端口和数据库位置：

```bash
PORT=9000 RADIO_DB=/tmp/radio.db python app.py
```

## 测试

```bash
python -m unittest discover -s tests -v
```

测试覆盖完整流程：排期、临时替换、播放日志、按日期对账；同时覆盖时间重叠、未授权地区、实播错节目、播出日归属、跨零点重叠 / 禁播 / 冷却 / 赞助间隔、旧数据迁移、移动失败保留原安排、并发 409 冲突与对账快照等场景。

## 主要 API

- `GET /api/state`：节目、排期、各播出日版本号和最近对账异常
- `GET /api/plan?date=YYYY-MM-DD`：某播出日的版本号与排期
- `POST /api/programs`：创建节目并授权地区
- `POST /api/programs/{id}/regions`：追加地区授权
- `POST /api/schedule`：创建排期（带 `base_version`）
- `POST /api/slots/{id}/move`：移动排期到新日期 / 时间并重新校验（带 `base_version`）
- `POST /api/slots/{id}/replace`：替换计划节目并重新校验（带 `base_version`）
- `POST /api/playout`：登记实播记录（快照播出当时计划）
- `POST /api/reconcile`：按播出日生成漏播、错播、时长偏差和超授权异常

准备排期时填写 `air_date`、`start_time`、`program_id`、`region`，并带上 `base_version`。页面会直接显示校验错误，不会保存失败的排期；遇到他人已改的播出日会弹出对方已改的时段。
